## 二、研究拆分与 Plan

程序按版本化模板创建必需研究骨架、问题清单、财务数据依赖和覆盖矩阵；模型补充公司特有问题及检索词，不能删除必需块或降低审核门槛。Plan 必须验证覆盖、公司/业务 ID、期间、依赖无环和预算；语义遗漏也要定向修复，不能只验证 JSON 结构。

必须支持以下 11 类分析块：

1. C01：公司概况与研究边界。
2. F01：财务增长与盈利能力。
3. F02：资产负债与偿债能力。
4. F03：现金流与利润质量。
5. F04：分业务财务表现与驱动。
6. F05：资本配置与股东回报。
7. I01：每项业务的行业分析。
8. B01：每项业务的公司分析。
9. V01：盈利预测与估值。
10. R01：风险与反证分析。
11. X01：公司整体综合与核心观点。

I01、B01 按业务实例化，其余各一个，N 项业务为 9 + 2N 块；两业务 13 块、三业务 15 块。分析块是调度单位，每块可执行多次调用，避免每个简单指标单独调用。

按 PRD 的依赖顺序调度：C01 确认范围，独立财务块与行业块并行取证，B01 衔接行业分析，F04 汇总分部表现，随后 V01、R01、X01。整体综合必须检查跨业务和跨章节矛盾，不能只拼接摘要。

## 三、上下文、取证与失败恢复

先定位问题相关的段落及表格，再按问题、期间和容量生成提取批次。保留表头、单位、比较列、脚注、合并范围和原文位置；不得只截取文档开头。完整来源持久化，各调用只接收相关事实、计算、精选证据及必要上游结论；同时传入足够的实际内容，不能只有不可读取的 ID。

实现覆盖矩阵、批次状态和上下文包的记录。结构化事实及引用由程序校验，无效结果隔离并登记，缺口只补查对应问题。禁止以“调用结束”代替“问题覆盖完成”。

按角色配置输入容量、输出预留、超时、并发、重试、块预算和全局预算。识别长度截断及不完整输出，缩小问题组或拆分批次后重试；语义遗漏只补缺项。不得无限重试同一大请求。

保存检查点和依赖版本。事实、期间或口径更新时，使受影响计算、块结论、章节、核心观点和审核失效；只重跑受影响内容。交付必须来自同一有效快照。支持经验证历史事实复用、最新披露增量获取与重述更新，不将数据库全部历史内容重新塞入提示。

## 四、财务同比硬性要求

“二、财务情况分析”必须包含同比对比表和解释性正文，并按 F01–F05 形成五个小节。同比不能只出现在三表、附录或泛泛描述中。

必需核心指标为营业收入、营业成本、归母净利润、扣非归母净利润、经营活动现金流量净额。表格覆盖最新三个已披露完整财年和最新已披露中期；最早展示财年的同比必须额外取得前序年度基数。中期与上年同长度期间比较，年度、单季度、累计期间和预测分开。

每项比较必须包含指标与口径、本期及数值、可比期及数值、增减额、同比或特殊变动状态、两期来源及计算引用。正文必须包含核心变化的实际数值、方向和同比/状态，并解释有证据支持的主要原因；无法确认原因时明确说明。

使用 Python Decimal 和注册公式计算，禁止模型自行重算或缺失填零。正文数字以结构化引用绑定事实/计算结果，表格、图表及导出保持一致。

- 正基数：同比 = 本期 / 同期 − 1，展示时转换为百分比。
- 零基数：百分比不适用，展示两期值及增减额。
- 负基数：按亏损收窄、扩大、扭亏或现金流状态解释，不使用常规同比增长率误导。
- 正利润转负：可以展示数学同比，同时必须说明转亏。
- 利润率、费用率和 ROE 等变化以百分点清楚表达。
- 较上年末变化与上年同日期的期末同比分别命名。
- 区分归母、合并、扣非、币种、单位、重述及业务范围。

核心同比缺失、错误或正文不合格必须返回对应块修复；仅有表格不能通过。补查和修复耗尽仍不合格时 blocked，不交付正式报告，不能降为 warning 或 limited。非核心限制按 PRD 明示处理。

## 五、终审与兼容性

保留结构、财务、证据、批判性、编辑五类终审；先执行确定性覆盖、比较、财务和数字绑定校验，再做语义审核。记录规则、严重性、责任块/小节、修复要求和报告快照，修复后重新验证受影响内容。

保留 completed、limited、blocked、failed 的区别，以及现有固定报告顺序、三表联动、五类收入模板、Bear/Base/Bull、单页流程、API、SSE、DOCX/PDF 和双协议 Gateway。blocked 不开放正式报告下载。

不新增账户、聊天、设置、上传、历史管理等页面，不新增第三类外部事实来源，不硬编码模型、密钥或价格。模型角色和预算保持后端配置。保留已有数据库、报告和运行记录；旧报告标记原规则版本，不冒充通过 v1.1。不得打印凭证或破坏既有服务与用户文件。

## 六、实施与验证

按 PRD 的 A–E 阶段推进：模板与覆盖 → 提取批次与上下文 → 财务比较与五块分析 → 分块写作、整体综合和局部终审 → 真实研究及成本评估。各阶段完成必要验证后继续，不停留在阶段计划。

新增有意义的契约、计算和故障场景测试，并运行项目要求的后端、前端、构建、端到端及导出检查；根据实际变更选择测试范围。至少覆盖：

- 两业务 13 块、三业务 15 块；遗漏与依赖错误可被发现。
- 长材料分批、截断后的拆批恢复、有限补查及预算耗尽。
- 500→550：+50、+10%；100→80：−20、−20%。
- 利润 40→−10：−50、−125% 并注明转亏。
- −100→−60：亏损收窄 40；0→10：同比百分比不适用。
- 30%→32%：+2 个百分点；中期同比不能混用全年或上年末。
- 核心同期缺失、有表无正文、归母口径错误均不能通过。
- 重述导致依赖重算、旧审核失效、局部返工及检查点恢复。
- 在线报告与导出数字及来源一致，已有记录保持可读。

先完成离线及 Mock 验证。若真实模式具备有效配置且有明确可执行的调用预算，开展 PRD 要求的代表性真实研究，记录实际 token、截断、遗漏、返工、耗时和交付状态；缺少配置或预算时明确列出未完成的真实验收，不宣称 Mock 等同真实成功，不为验证发起无预算的大规模调用。

更新实现说明、配置示例、任务清单和运行说明，按实际证据标记完成。每项要求应能对应代码与验证结果。实施期间持续报告关键进展，遇到常规问题自行处理；只有确实缺少必要信息或授权时才询问。
