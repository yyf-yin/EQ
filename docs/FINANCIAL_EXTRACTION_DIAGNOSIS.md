# 2026-10-16 年报已有数据却提示核心输入缺失

核查对象：本地研究记录 `231ce61748f543dba1de194b9dac429d`。核查只读取原业务数据库；验证写入独立临时数据库，没有修改原研究结果，也没有发起真实模型请求。

## 已确认的原因

1. 年报窗口尺寸只扣除了基础提示和字段定义，没有计入后续添加的大量待填目标，以及最终请求编码和模型输出预留。执行记录有 34 次 `fixed_extract` 容量超限失败，另有 3 次输出截断失败（统计单位为失败尝试）。这些不是原文缺少数据。
2. 原表同时有年份、附注编号、同比百分比、调整前/调整后子列；旧校验要求“数字数量等于年份数量”，会拒绝有效行。PDF 在“归属于上市公司股东的扣除非经常性损益的净利润”等名称内部换行，也会使后续指标匹配失败。
3. Brief 的正文窗口被排在前面的 2023 年报占满，模型明确写出“未提供2024年及以后年报”，实际上传包含 2024、2025 年报。程序当时只检查已入库事实，没有用完整上传清单检查最新年报，最终错误选择 2021–2023 为历史期、2024–2026 为预测期。
4. 失败窗口只保存粗粒度失败状态；页面把资料缺失、提取失败、校验拒绝合并成核心输入缺失。旧记录已进入质量阻断，重复点击继续不能修复这些输入。

## 本次修复

- 按完整请求（目标、schema、协议编码及输出预留）计算窗口容量；保存窗口尺寸，保证部分执行后的重放边界不随已锁定目标变化。
- Brief 提供完整年报清单，给每份文件分配正文窗口；按清单最新完整财年验证历史和预测期间，发现遗漏时定向修正。
- 表格校验识别附注、序号、同比列、当期/上年同期，以及标准三年表中的调整前/后子列；保留金额、期间、会计口径一致性检查，含糊的表头仍拒绝。
- 指标名称匹配忽略 PDF 排版空白，原始引用保持不变。
- 修正“非年报必须 values 为空”与季报/中报可提取之间的提示冲突；要求完整原文表头和数值列索引。
- 保存模型失败类型和说明；核心缺口提示明确说明提取/校验失败不等于未披露。

## 验证范围与使用方式

新增合成测试覆盖附注编号、序号、换行、同比、重述比较列、较大待填目标请求、最新年报选择。使用本次保存的真实原文，离线验证了 2023 年扣非归母净利润、2026 半年报营业收入和扣非归母净利润的准入。该抽查不等于整份真实研究已跑通。

重启程序后，用原来这组文件新建研究。预期展示历史年度为 2023–2025，预测年度为 2026–2028，额外收集 2022 年用于同比，并收集 2026H1 / 2025H1。旧任务保留阶段成果；不要修改旧任务状态来绕过审核。真实模型仍可能漏提取、截断或生成无法定位的引用，后续缺口应按具体失败记录定位，不能直接填零或放宽真实性审核。

## 复核后的第二轮修复（2026-10-16）

复核结论：年度规划已修好，校验改善（2026 半年报被拒的 207 个值中 144 个通过），但容量问题转成了窗口过小（2,300–5,800 字，2024 年报 75 个窗口，首轮调用约 201 次），截断仍直接判失败。根因是每个年报窗口带 805–1,150 个待填目标：每个单季度都挂全部 115 个字段，累计期间挂到了年报上，`supports_period` 又按正文出现的年份绑定。

本轮修改：

- 年报只绑定本年、前两年和本年 1Q–4Q；单季度只要求分季度表的四项指标；比较基年只要求核心与模型字段；缺本期报告时只绑定最近一份报告。
- `open_targets` 改为按期间分组的紧凑格式。
- 截断、JSON 不完整或超限时窗口对半拆分重提。输出上限保持 32000：实测 71 次提取中思考约占输出 63%，12000 会截断 24 次。填槽改用独立的 `slot_extractor` 角色，可单独配置无思考模型。
- 修复负数被识别为区间（财务费用、投资/筹资现金流、现金净增加额等整行被拒的主因）。
- 占位符占列、行尾未标注的增减列、期末/期初余额等列头。
- 拒绝原因传给修复请求；Brief 年度由程序写入。

尚未处理：数值提取只发送财务章节（主要会计数据、三张合并报表、分季度表）；行业网页检索的低质量域名过滤。下次用同一组文件新建研究的目标：零容量报错、零截断失败，2022A–2025A 与 2025H1、2026H1 核心字段齐全，提取调用少于 80 次。
