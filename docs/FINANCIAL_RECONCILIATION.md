# 财务核验与冲突处理

完整改进方案见 [上传参考资料、数据来源优先级与人工确认权限设计](SOURCE_AUTHORITY_DESIGN.md)。其中启动页上传和参考资料优先采用已实施：已覆盖字段不再外部取数，上传资料内部冲突由人工选择；实际范围见 [参考资料上传](REFERENCE_UPLOADS.md)。财务接口及完整人工直接录入等仍为设计内容，下文描述原有自动核验机制。

流程：保存原始候选 → 规范单位 → 分组核验 → 定向补查 → 证据裁决 → 选择计算输入 → 仅重算受影响依赖 → 最终审核。

来源的标题、发布日期变化只记录差异，保留首次元信息。正文变化形成独立来源记录。不同网站的不同数据都保留，不覆盖原记录，不按搜索时间或多数票选数。

财务候选按公司、指标、期间、规范单位、合并/母公司/分部范围、分部、实际/预测及币种分组。元、千元、万元、百万元、亿元规范为人民币百万元，百分比规范为 ratio；禁止未证明的汇率转换。期间不做模糊合并。会计口径即使数值相同也视为冲突，不能混用。

数值相同且口径一致时选择一个确定的事实引用。数值或口径不同，真实模式按组定向检索年报、原始公告及更正/追溯调整，默认最多两轮，配置 CDR_MAX_CONFLICT_CHECKS 控制（0–4）。成功的检索、提取及摘要保存到本任务执行记录，暂停或断网后复用；补查轮次跨重新规划累积。新候选改变候选集合时原补查授权失效，只在剩余轮次内补查。仍无法确认时保留冲突与缺口。

自动采用原始披露要求：可信交易所/披露平台的 HTTPS 精确域名或子域名、公司名称、可在原文定位的摘录、单一明确年度/期间、指标、单位及合并/母公司/分部范围，且数字对应指标。完成定向补查后，同口径原始披露一致时可优先采用并记录原因。两个原始披露数值不同，须提供同指标、同口径、同单位且明确方向的更正前后数值。仅有“更正公告”标题、发布日期或模型生成的 supersedes 不足以裁决。

自动更正识别目前支持明确的“由…更正为…”及“更正前/后、调整前/后、重述前/后”同单位数值；多年度表、单位仅在远处表头或无法定位方向的复杂表格会保留待核实状态。其他发行人网站或资料不会被删除，只是不凭来源名称自动提升权威等级。程序不让模型自由投票裁决；资料不满足证明条件时仍需补充清晰的原始披露。

原始候选永不删除或覆盖，裁决后的事实集合才进入计算。未选用或冲突事实的数字证据不进入章节/假设上下文。裁决变化记录依赖块失效原因；依赖输入变化的计算、同比和预测失效；块分析与写作按各自输入快照复用，无关块保留。相同输入及公式版本的历史计算复用并复算校验。期初余额、分部预测收入及核心同比均为关键依赖。缺失时不生成基于冲突的假设和预测；其他研究块继续。关键冲突补查耗尽，在最终审核保存审核问题并阻止正式交付。

前端“阶段成果”可查看财务冲突核验：候选值、单位、会计口径、事实/来源/证据 ID、选用结果及理由。评估包包含 fact_decision.json、fact_verification.json 和 source_metadata.json，原始候选在 fact.json，未选用与待核实材料有独立标签。

核验策略及补查参数进入续跑兼容性清单。升级前旧断点不能绕过新核验直接交付；重启后最近一个兼容的未完成任务可在页面继续，其它情况新建独立研究或上传成果包，旧材料保留。

关键数据经自动补查仍无法核实，进入独立人工待办；其他采集继续，计算分析入口等待证据核验完成。见 [人工介入说明](HUMAN_INTERVENTION.md)。
