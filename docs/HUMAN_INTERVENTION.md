# 人工数据介入

完整改进方案见 [上传参考资料、数据来源优先级与人工确认权限设计](SOURCE_AUTHORITY_DESIGN.md)。启动页上传和参考资料优先采用已实施，人工可以选择上传参考资料中的候选解决其内部冲突，无需外部公告证明；实际范围见 [参考资料上传](REFERENCE_UPLOADS.md)。完整的独立人工直接录入、修订及计算后修改等仍为设计内容，下文描述原有反馈机制。

人工介入由 `HumanInterventionAgent` 管理持久化待办。它整理问题、收集反馈、验证依据和更新裁决；定向补查复用现有 researcher。待人回复时不持续调用模型，也不占用研究执行名额。

## 流程

- 每个采集子任务提交结果后检查冲突，提前发布待办；其他独立采集继续，原有依赖和并发限制保留。
- 自动核验和有界补查仍运行。自动解决的问题关闭；补查耗尽的核心缺失或冲突留待人工处理。
- 公司、指标、期间、合并/分部范围和候选集合绑定待办版本；候选变化时旧反馈失效。
- 计算入口重新核验反馈和全部关键依赖。有公式依赖或 critical 优先级的缺失、冲突未解决时，任务进入 waiting_human。任何财务计算、预测和分块分析均不在此状态继续。
- waiting_human 释放 Runner 名额，并保留图检查点、已完成执行单元和阶段成果。反馈提交后在预算、会话和兼容性允许时自动排队续跑。
- 已主动暂停的任务提交反馈后仍保持暂停，点击继续研究才处理。
- 已进入计算的待办只读，防止迟到反馈被误认为影响已冻结的本轮输入。审核返工重新采集时重新开放并检查门槛。

## 前端操作

研究进度中新增“人工数据核验”。每项显示指标、期间、范围、是否阻断、候选数值、会计口径、原文摘录、来源和反馈错误。

1. 选择已有候选：给出处理依据；所选事实必须具有可定位的原始披露证明。两个同口径原始披露值不同，仍要求明确更正前后证据，不因人工点选而直接放行。
2. 补充或修正：从本任务已经收集的来源提供完整原文摘录、位置、数值、原文单位及会计口径。系统验证摘录确实存在，并核对公司、期间、指标、单位、范围和数字。修正生成新证据和候选，不覆盖原记录。非 reported 会计口径还须有原文说明。
3. 定向补查：提供新的查询方向或公开披露链接。链接通过现有公开 URL 检查和下载大小限制读取；研究提取和补查结果按原任务保存。失败和暂停沿用原有恢复机制。

非关键披露缺失可以保留限制。人工反馈不支持把无来源估计写成已核实历史事实，也不支持跳过质量审核。数字证据只进入使用对应事实的分析块；重新生成的预测假设若内容和依据完全一致，保留原 ID，避免无关业务因随机 ID 变化重算。

## 保留与恢复

`human_issue`、`human_feedback`、`human_resolution` 按 run_id 保存；JSON/ZIP 阶段导出包含完整允许字段，Markdown 包含问题和反馈摘要。反馈提交为原子版本检查，重复同一请求复用收据。

暂停、预算增加、数据隔离、重启后页面继续规则和正式交付审核继续适用。waiting_human 也属于重启后可在页面继续的未完成任务。策略进入恢复兼容性清单；升级前的兼容任务仍可续跑：计算前检查点会经过新门槛；已进入计算的真实任务仅在关键输入均已核实且无关键冲突时允许迁移。其余旧断点会拒绝续跑，可保留导出后在首页手动输入公司新建研究，避免旧缓存绕过计算门槛。已完成报告的读取与下载不变。

## 验证

测试使用隔离数据库、模拟模型与 HTTP。覆盖提前发布、关键门槛、原文补充、无证据选择拒绝、冲突更正要求、任务隔离、版本过期、幂等、原图续跑、暂停后的反馈、阶段导出和界面提交；浏览器检查桌面、手机和刷新后待办。
