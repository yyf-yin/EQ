# 提速迭代验收（2026-10-11）

本轮优化保持研究范围、必需问题、原文定位、财务口径、同比门槛、章节长度、反思、独立终审、预算和暂停续跑要求。没有修改 `.env`、模型配置、运行中的业务数据库或已有报告。

## 实现

- 新任务使用持续补充空闲槽位的有界调度。只有依赖块的全部任务完成后，后继任务才可启动；分块分析同样保留依赖门槛。
- 单个研究任务内部的独立提取批次可以并行，仍受配置中的角色和全局并发上限约束。没有提高现有并发配置。
- 独立章节及情景/年度假设并行生成。每章保留完整反思与修订，核心观点仍在各章节之后生成，跨情景模型冲突仍报错。
- 批次组建计入完整协议请求，包括提示词、任务、Brief、JSON Schema 和输出预留；元数据无法容纳时仍保留原有拆分/缺口路径。所有原文窗口、表头、单位、脚注和定位偏移保留。
- 模型请求仅携带一份原文，表头/单位/脚注放入 `metadata`，原文放入 `content`；完整原始窗口仍保存于审计记录。
- 成功批次复用后保持 `validated` 和完整结果，修复原来可能被重新写成 pending/空结果的问题。组批变化时，仅复用全部窗口精确匹配且校验成功的批次。任务、Brief、模型、提示词或 Schema 改变会使复用失效；隔离批次继续走原校验/修复路径。
- 并发结果按输入顺序合并，批次复用按来源窗口顺序排列，防止完成先后顺序影响后续提示和断点身份。
- 某项工作失败后停止派发新工作，等待已启动工作保存结果再抛出异常。暂停及失败续跑继续复用已提交成果，累计预算不清零。
- 多项并发工作失败时，仍按输入顺序决定异常优先级，保持质量阻断与执行失败的分类；提高续跑预算或调整并发/超时不会使成功提取结果失效。

策略通过 `execution_meta/performance` 固定在任务内。已有检查点或执行单元的旧任务沿用原输入/调度策略；新任务使用 `throughput-1`，此后暂停、重启也保持该策略。原有成功批次状态修复适用于两种策略。后端重启载入代码后，新建研究自动启用优化。

## 验证

- 完整 Mock HTTP 流程分别执行旧策略及新策略，均通过研究、预测、写作、反思、审核及导出，均产生九个预测情景/年度结果。两种策略均记录 148 次模型请求，其中写作和反思各 14 次；没有靠省略步骤提速。
- 新增调度、完整请求容量（OpenAI JSON/tool/native、Anthropic）、原文覆盖、三轮复用、输入变化失效、批次失败保存及续跑回归。
- 暂停/重启、预算调整、成功同伴保存、已提交模型步骤复用等专项回归通过。
- 全量后端回归：164 项通过（367.27 秒）。最终异常优先顺序更新后的调度/续跑专项：21 项通过（97.67 秒）；成功取证在预算/并发/超时调整后仍可复用的最终专项：11 项通过（2.34 秒）。专项包含重叠用例，不相加宣称全量数量。

Windows 沙箱会阻塞 asyncio 初始化，测试在获准的沙箱外运行。全量测试进程显式设置 `CDR_MODE=mock`，防止本地真实模式配置干扰默认模拟测试；不改用户配置。数据库及导出文件均位于 `work/pytest-throughput-*`，模型和搜索使用 HTTP 夹具。

## 性能证据及边界

执行 `./.venv/Scripts/python.exe scripts/benchmark_throughput.py` 可复现合成取证子图基准。每次运行新建隔离数据库，使用同一份合成披露、相同角色并发上限和固定 0.1 秒 Mock HTTP 延迟；不请求真实模型或搜索。

本次结果保存于 `work/throughput-benchmark/be8ecf16c5174b0fb778d5c79f302fef/result.json`：

| 项目 | 旧策略 | 优化策略 |
|---|---:|---:|
| 取证子图耗时 | 5.423 秒 | 2.773 秒 |
| 提取 HTTP 请求 | 21 | 20 |
| 压缩 HTTP 请求 | 1 | 1 |
| 唯一财务事实 | 1 | 1 |
| 唯一证据 | 1 | 1 |

该基准耗时减少 48.87%，事实和证据的完整数据摘要一致，两者均无警告或缺口。这是受控子流程基准，不代表真实公司完整研究的提速比例或质量验收。

只读重构此前真实运行的 508 份取证上下文后，重复原文精简使完整请求的保守 UTF-8 字节估算由 8,958,358 降至 7,508,102，减少 16.19%。这不是供应商 Token 或账单统计；没有向真实服务重发这些请求。

真实整轮耗时仍需新任务实测，受检索网络、供应商延迟、输出长度、资料质量和修复次数影响。本轮没有另行发起收费的真实公司研究。
