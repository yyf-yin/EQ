## 1. 产品目标与边界

用户输入一个上市公司名称或代码，系统自动完成取证、分析、预测、审核和报告交付。优先支持中国 A 股非金融企业。前端保持 React/TypeScript/Vite/Tailwind 单页，提供输入、开始研究、真实任务进度、报告阅读和 DOCX 下载；环境支持时可下载 PDF。

不增加账户、聊天、设置、上传、历史管理、模型编辑或 Skills 创建页面。模型、调用预算、资料目录和数据源凭证由后端配置管理。已有 Skills 可以复用，未安装 Skills 时核心流程也必须运行。

唯一外部事实来源仍为 Web Search 与 Local Datasource：公开网页、公开下载文档，以及指定目录中的 PDF、DOCX、XLSX、CSV、TXT、Markdown、HTML、JSON。统一适配层负责检索、读取、结构化和来源登记。模型输出不是事实来源；来源内容作为不可信数据处理，不执行其中的指令。不新增第三类金融 API 或 MCP 数据源。

历史范围为最新披露的三个完整财年及最新可用中报/季报；预测范围为未来三个财年。以研究截止时间前实际披露的材料判断“最新”，不得按系统年份推断已有财报。实际值、预测值、年度、累计期间和单季度必须分开。为计算展示期的同比，可以额外读取前一比较年度，详见第 5 节。

## 2. 本次变更与成功标准

| 方面 | 当前架构的主要缺口 | v1.1 目标 |
| --- | --- | --- |
| Plan | 模型生成研究任务，程序校验对象并补公式依赖；不能据此保证每个必需研究维度都被覆盖 | 程序生成必需骨架与覆盖矩阵，模型仅细化问题；遗漏或无效 Plan 定向修复 |
| 资料提取 | 任务内可向单次调用传入较多来源内容 | 先筛选相关段落和表格，再按问题、期间及容量分批提取 |
| 分析和写作 | 已分任务、分章节，但部分上下文仍携带公司全量数据 | 每块只接收完成该块所需的证据、数据和计算；跨块通过引用和精简结论衔接 |
| 同比 | 已有 YoY 公式与历史指标，不能保证财务章节包含完整同比表和正文 | 核心指标必须有本期、同期、增减额、同比或特殊变动状态，以及正文解释 |
| 失败恢复 | 已有有限重规划和定向返工 | 定位到问题、资料批次、分析块或报告小节，修复后只更新受影响依赖 |
| 质量和成本 | 离线 Mock 验证不证明真实模型能完成复杂研究 | 记录真实输入/输出 token、截断、有效覆盖率与返工；通过真实代表性公司验收 |

成功不等于调用次数更少。首要标准是必需问题覆盖、证据与数字一致、财务同比合格、有限预算内可交付。拆分通常减少单次上下文负担，但会增加固定提示及调度开销；总 token 是否下降必须实测，不在 PRD 中承诺固定降幅或某一模型必然完成。

## 3. 研究框架：11 类分析块

研究以分析块为调度单位，块内按问题与资料批次执行。块不是单次调用的同义词，一个块可包含检索、提取、计算、分析、校验和局部修复等多次调用。避免把每个简单指标都拆成独立模型调用。

| 模板 ID | 分析块 | 核心问题与输出 | 主要依赖 |
| --- | --- | --- | --- |
| C01 | 公司概况与研究边界 | 公司身份、发展、股权与治理、业务划分、报告口径、披露时间与研究范围 | 公司识别、权威公司资料 |
| F01 | 财务增长与盈利能力 | 收入、成本、利润同比；毛利率、净利率、费用率及盈利变化原因 | 可比财务事实、同比和比率计算 |
| F02 | 资产负债与偿债能力 | 资产、负债、现金、有息债务、应收与存货变化；杠杆、流动性和营运风险 | 资产负债表、附注、确定性计算 |
| F03 | 现金流与利润质量 | 经营现金流同比、利润与现金匹配、营运资本、资本开支和 FCF | 现金流量表、利润、资产负债及附注 |
| F04 | 分业务财务表现与驱动 | 各业务收入、毛利、占比和同比；量、价、结构对总体变化的解释 | 业务口径、分部披露、I01/B01 的相关证据 |
| F05 | 资本配置与股东回报 | ROE/ROIC、投资、研发、分红、回购与融资；资金使用和回报变化 | 三表、附注、股本与分配披露 |
| I01 | 每项业务的行业分析 | 市场需求、规模、周期、竞争、价格、政策和产业链 | 每业务行业证据 |
| B01 | 每项业务的公司分析 | 产品、客户、渠道、产能、量价、竞争位置、壁垒和业务展望 | 每业务公司证据、对应 I01 |
| V01 | 盈利预测与估值 | 分业务假设、未来三年三表、Bear/Base/Bull、估值与敏感性 | F01–F05、各业务 I01/B01、假设与计算 |
| R01 | 风险与反证分析 | 主要结论的反例、发生机制、触发条件、影响方向和证据缺口 | C01、F01–F05、各业务 I01/B01、V01 |
| X01 | 公司整体综合与核心观点 | 跨业务协同与矛盾、整体财务约束、核心判断、催化剂与关键不确定性 | 经校验的前述块；最后执行 |

C01、F01–F05、V01、R01、X01 各一个；I01、B01 按业务实例化。因此，N 项业务有 **9 + 2N 个分析块**：两项业务为 13 块，三项业务为 15 块。资料批次、预测内部子任务和写作任务不计入此数量。

默认调度顺序：C01 确认范围后，独立财务块 F01/F02/F03/F05 与各业务 I01 可并行取证；B01 衔接对应 I01；F04 汇总分部事实及业务驱动；V01 → R01 → X01 依次完成。并行块共享版本化事实，不互相等待对方的最终结论。X01 或终审发现新问题时以有界返工更新对应依赖，不在初始 Plan 中引入循环。

财务章内的 F04 负责量化分业务贡献，业务章的 I01/B01 负责行业与公司经营机制，共用已存证据，避免重复取数。没有披露完整业务财务数据时保留业务分析，标注分部数据限制，禁止分摊或估造业务收入、利润。

X01 必须进行整体判断，不能简单拼接各块摘要。至少检查收入增长与现金流是否匹配、业务预测与总量约束是否一致、估值是否被证据支持、不同业务的资源竞争和集中度风险。未解决的重大矛盾回到对应块修复。

## 4. Plan、调度与有界研究流程

### 4.1 程序骨架与模型细化

1. Company Resolver 确定公司身份、证券代码、市场和行业，排除同名主体；真实模式无法确认时停止。
2. Research Brief 确认截止日期、实际披露范围、年度/中期口径和业务清单。业务清单须有来源支持，不能只来自模型记忆。
3. 程序按版本化模板生成 ResearchBlock、必需问题、必需财务数据、覆盖矩阵和依赖关系。财务核心指标及同比比较期由程序确定。
4. 模型在骨架中补充公司特有问题、检索词、重要性和可选问题；不能删除必需块、降低硬性条件，或以可选问题替代必需问题。
5. 程序检查公司/业务 ID、期间、必需覆盖、引用、依赖无环、任务预算和输出结构；计算计划只允许使用注册公式，并展开其事实依赖。
6. 不合格 Plan 返回具体缺项进行有界修复。结构有效但遗漏必需问题也算失败。无法修复则使用已验证的标准骨架继续可执行部分；身份、口径或核心依赖仍无效时阻断。

覆盖矩阵至少包含 block_id、question_id、required、所需事实/证据、当前状态、缺口、责任任务与验证结果。问题状态包括未开始、取证中、可分析、已校验、缺失、冲突；“任务运行结束”不能自动等同于“已覆盖”。有来源支持的“未披露”可作为非核心问题的受限结果，不能视为已取得财务核心比较数据。

### 4.2 资料批次与上下文

检索 → 来源登记与去重 → 段落/表格定位 → ExtractionBatch → 结构化提取 → 程序校验 → 证据库 → 缺口检查 → 定向补查 → 块分析 → 块校验。

- 一个提取批次对应清晰的问题组、公司/业务、指标与期间，不向单次调用塞入公司所有研究问题和所有文档。
- 根据问题选择资料窗口。表格必须保留表头、期间、单位、合并/母公司标识、脚注及相关比较列；不能只机械取文档开头或固定前若干来源。
- 大表按可解释的行组或期间拆分，保持必要上下文；跨页表合并后记录页码和原始位置。
- 同一批次可提取一组相近指标。相关来源冲突时允许放入同一比较批次，不为控制容量丢弃冲突证据。
- 提取输出必须带原文定位、来源、口径和事实 ID。数字、原文引用及来源引用由程序校验，未通过项隔离并登记问题；不得静默丢弃后声称研究完成。
- 生成块分析时传入该块的事实、计算、精选证据与必要上游结论。传入 ID 同时传入完成判断所需的实际值及原文摘录，不能只给模型无法读取的 ID。
- 块分析输出结论、支持证据、反证、缺口和置信限制，不输出面向用户的内部推理过程。

上下文包必须记录所选 ID、版本、筛选理由和容量。不能用模型自由压缩取代事实保存；压缩摘要需能回溯原始证据。完整资料留在持久层，只有问题相关内容进入模型。

### 4.3 预算、截断与局部恢复

按角色配置输入容量、预留输出、最大输出 token、超时、重试数、并发、块调用预算与全局预算。容量根据具体模型上下文和服务限制配置，不写死供应商或模型名。调用前检查输入加输出预留是否可容纳；无法精确计数时明确标记估算方法和误差，不能把字符数当成 token。

首轮建议上限：同一输出结构/语义修复 2 次、同一问题补查 2 轮、终审定向返工 2 轮；均外置配置并接受全局预算约束。并发有上限，限流退避也受时间和预算约束。

输出截断或 JSON 不完整：识别 finish_reason/协议停止原因，保存诊断，缩小问题组或拆分批次后重试。必要时调整输出预留，但不能无限重复同一个大请求。结构合法但核心问题未答：返回缺项，只补对应问题。事实冲突：查同口径原始披露并核对重述。核心证据不足：局部补查，预算耗尽后阻断。工具或模型故障：有界重试后记录明确失败。

每块、批次、计算和写作保存检查点。修复事实或期间口径时，通过依赖图使受影响计算、块结论、章节、核心观点及终审结果失效；未受影响的任务可复用。最终交付必须使用同一有效快照，禁止旧终审批准新报告。

### 4.4 历史复用与增量更新

SQLite/后续内部数据库保存来源、披露日期、财务事实、原文位置、计算及有效版本，不构成新的外部事实来源。再次研究可以复用已校验历史数据，检索最新披露、实时变化和历史缺口；原始历史证据仍保留，不能只存模型摘要。

复用需要匹配公司、期间、单位、合并范围、会计口径和重述版本，并检查来源有效性。公告重述触发历史版本更新与下游失效；行业价格、订单、股价和估值时点按配置刷新。数据库有历史记录不代表必须全部放进提示。历史复用的成本效果以实际检索与调用记录验证，不承诺实时资料完全取代历史基准。

## 5. 财务分析：同比信息为成稿硬性要求

### 5.1 展示范围和核心指标

“二、财务情况分析”必须同时包含财务数值对比表与解释性正文，不能用“增长较快”“有所下降”替代数字，也不能只把同比放在“六、财务三表”或附录。

必需核心指标：**营业收入、营业成本、归母净利润、扣非归母净利润、经营活动现金流量净额**。合并净利润与归母净利润分别保存、分别标注；不得互换，扣非净利润也不得由模型估算。派生毛利、利润率等按注册公式计算。

核心表覆盖最新三个已披露完整财年的本期值和同比比较；为计算最早展示财年的同比，读取额外一个前序完整财年的可比基数。最新可用季报/中报另设表，与上年同期比较。如果没有最新中期披露，不构造中期数据；如果已有披露但尚未取得，视为缺口。

已取得三年数据但未取得最早展示年度的前序基数，不得假装该年度同比已完整。按核心比较数据缺口补查；确实无法取得或无法统一口径时，阻断本版本的正式成稿。

### 5.2 财务表的固定字段

| 字段 | 要求 |
| --- | --- |
| 指标与口径 | 明确归母/合并、扣非、实际/预测、货币与单位 |
| 本期及本期值 | 明确年度、累计中期或单季度，不用“最新”替代期间 |
| 可比期间及同期值 | 同公司、同期间长度、同合并范围和会计口径；采用可比重述值时说明 |
| 增减额 | Python 计算：本期值 − 可比值，保留正负和数值单位 |
| 同比/特殊变动状态 | 正常同比百分比，或零基数、亏损收窄/扩大、扭亏、转亏等明确状态 |
| 来源与计算引用 | 两期事实、必要口径说明以及 comparison/calculation ID 均可回溯 |

表头统一注明金额单位和舍入规则。计算保留 Decimal 精度，展示时才舍入。舍入后方向不能与原数值相反；接近零的变化显示适当精度或说明。正文、表格、图表和导出使用同一事实及计算结果。

### 5.3 可比性与特殊情况

- 年度同比比较年度；累计中期同比比较上年同长度累计期间；单季度同比比较上年同季度。不得拿上年全年与当期前三季度计算同比，不得把环比标为同比。
- 本期与可比期均按统一币种、单位、合并范围和会计口径处理；未经证实的换算不执行。重述优先采用最新披露中的可比数据，并保留旧值、更新依据和引用。
- 可比值大于零时：同比 =（本期值 / 可比值 − 1）× 100%。本期转负仍可以展示数学结果，但必须注明转亏或转为净流出，不能只写“下降”。
- 可比值为零时：百分比显示“不适用（同期基数为零）”，展示两期值及增减额；不得显示无限大、任意百分比或零增长。
- 可比值小于零时：不套用常规同比增长率解释业绩。展示两期值、增减额和经济状态；利润由负转正标“扭亏”，持续亏损按亏损金额判断“收窄/扩大”；现金流按净流入/净流出说明。若另行使用绝对基数变动率，必须单独注册公式、标注名称，不能伪装成通常同比。
- 毛利率、净利率、费用率、ROE 等比例变化优先用**百分点**：32% 对比 30% 为增加 2 个百分点，不能写成同比增长 2%。
- 资产负债表期末值可展示较上年末变化；若用上年同日期比较则标明期末同比。两种比较分列命名，不能把中期相对上年末变化直接写成同比。
- 分业务口径变化时先建立经披露支持的映射；不能比较不同业务范围，也不能把分部利润率冒充公司毛利率。缺乏可比披露时注明原因。

### 5.4 五块财务分析的成稿内容

| 财务块 | 必须形成的内容 |
| --- | --- |
| F01 | 核心收入、成本、归母和扣非利润的对比；毛利率、费用率及盈利能力变化；收入增长与利润变化是否一致 |
| F02 | 资产负债规模与结构、现金和有息债务、应收与存货变化；偿债与资金占用；明确各项比较基准 |
| F03 | 经营现金流核心同比；与利润的差异及营运资本解释；资本开支、FCF 与现金来源/用途 |
| F04 | 有披露支持的各业务收入、占比、毛利及同比；业务增减如何影响总收入和盈利；可用量价证据及披露限制 |
| F05 | ROE/ROIC 和资本效率变化；投资、研发、分红、回购、融资与股东回报；使用可验证数据及适用性说明 |

正文至少分别解释收入、归母净利润、扣非归母净利润和经营现金流的主要变化，营业成本变化在盈利分析中说明。每项叙述包含本期数值、可比数值、增减方向和同比/特殊状态，并关联事实或计算引用。对重大变化给出有证据的原因；原因未被披露支持时明确“驱动原因尚未确认”，不能把猜测写成事实。

示意文字：“本期营业收入为 550，上年同期为 500，增加 50，同比增长 10%；……”只是格式示例，不能进入真实报告充当事实。

### 5.5 确定性校验与硬性门槛

程序检查核心指标、展示期、比较期、口径、来源、两期值、增减额、增长率/特殊状态及正文数字绑定。表格由程序生成；正文数字以结构化引用绑定事实/计算结果，渲染时统一格式，不依靠模型自由重算。数值检查和同比覆盖检查必须通过，之后再由语义审核检查变化解释是否成立。

核心同比缺项、错期间、错口径、同比算错、负基数误导、把百分点写成百分比、正文遗漏必需变化或与表格矛盾，都必须返回对应财务块修复。仅有同比表而正文不合格不能通过。

补查和修复耗尽仍无法满足核心比较要求时，状态为 **blocked**，保存诊断与未完成工作，不交付正式报告。不得把核心同比缺失降级为 warning 或以 limited 状态交付所谓已完成财务分析。非核心分部数据、非关键背景或不适用指标可有明确限制；受限报告必须保留所有核心硬性要求。

## 6. 财务计算、预测与估值

沿用 Python Decimal 和 Formula Registry；模型只提出分析、假设和可选计算需求，不自行生成未校验财务结果。统一注册 YoY、CAGR、各利润率、ROE、ROIC、杠杆、流动性、周转、FCF、EPS、PE、PB、EV/EBITDA 等公式及输入单位、适用条件和版本。不能用缺失值填零。亏损、负权益或其他不适用情形明确标注，不给出误导的比率。

V01 内部分三层：按业务提出并审核假设；程序汇总未来三年三表；估值及情景解释。保持量价、产能利用率、用户 ARPU、市场份额、历史增速五种收入模板，按业务适用性选择，不要求每家公司都用同一模板。

预测假设引用历史趋势、行业及公司证据，标注推断与不确定性。成本、费用、税、折旧、资本开支、营运资本、债务、利息、现金和权益通过确定性模型联动；禁止任意平衡项。Bear/Base/Bull 共享明确的情景定义，差异来源可追溯。EPS 的利润与股本口径一致；价格、股本及估值采用明示时点。实际与预测不得混在历史同比表中。

三表失衡、单位错误、关键利润或现金口径错误直接阻断，不能靠模型重写文字“修正”。简化非金融模型的适用范围和未建模事项在报告中说明。

## 7. 报告生成与跨块整合

固定一级结构继续为：核心观点、目录、一、公司简介、二、财务情况分析、三、公司业务、四、盈利预测与估值、五、风险提示、六、财务三表、七、免责声明。每项动态业务在业务章包含行业情况、公司情况；财务章采用 F01–F05 五个小节。分析块数量不改变一级章节顺序。

先完成取证与计算，再按块/小节写作；较大章节由程序合并，不要求单次调用输出整章。写作上下文包含对应块分析、选定事实、比较结果、来源与必要跨块结论，不包含全公司原文、所有历史调用或全部无关假设。

X01 最后生成核心观点，并检查跨章节一致性；目录根据实际结构生成。程序生成三表、同比表和图表数值，在线 HTML 安全渲染；HTML、DOCX 和 PDF 使用相同结构化报告模型。DOCX 必须可下载，PDF 按环境能力提供；只有实际排版后才能声明页码。

## 8. 终审、不合格处理与交付状态

终审保留结构、财务、证据、批判性和编辑五个维度。结构/财务/数值绑定/核心同比覆盖由程序先行检查；语义审核以章节包和块间对照材料为主。总审获取核心结论、覆盖矩阵、关键财务表、各块结论、风险和未解决问题，必要时定向读取相关证据，不用全量材料替代审核设计。

每个问题记录 severity、规则、责任块/章节、受影响引用、修复要求和验证状态。所有问题及审核引用与报告快照关联。模型无权修改程序硬性规则的严重性。严重错误和证据缺口局部修复；修改上游数据则重算并重审全部受影响内容，修改文字则重审该小节及相关一致性检查。修复不能删掉必需段落或降低必需覆盖。

| 结果 | 条件与行为 |
| --- | --- |
| completed | 核心覆盖、同比、财务和证据检查全部通过，无未解决的阻断问题；可阅读、下载 |
| limited | 核心硬性要求通过，仅存在明确披露的非核心限制；报告显著说明限制，可阅读、下载 |
| blocked | 核心数据/同比、财务或重大证据问题无法修复；显示原因和已完成任务，不开放正式报告下载 |
| failed | 工具、模型、存储等执行故障在重试后仍使流程无法继续；保存检查点与原因，支持适用情况下恢复 |

用户界面显示实际任务状态、正在处理的块、补查/返工原因和最终限制。不得显示虚假完成百分比，不泄露系统提示、内部推理和密钥。超出预算和停机原因必须可见，不能无限运行。

## 10. 接口、运行及兼容性

保留 POST /api/research（输入 company）、GET /api/research/{id}、events、report、download 及 /api/health；已有中断/恢复能力继续适用。SQLite 持久化，SSE 支持 Last-Event-ID 与查询游标，刷新恢复同一任务。新增块和批次信息通过兼容的事件/状态字段表达，不增加用户配置步骤。

沿用统一 Gateway 与外置角色路由，支持 OpenAI-compatible Chat Completions 和 Anthropic-native Messages，禁止硬编码模型、价格或密钥。真实模式缺少必要配置应明确报错；Mock 模式使用虚构资料并显著标识，不能代表用户输入公司的真实研究结果。

## 11. 验收场景

| 类别 | 必须验证的行为 |
| --- | --- |
| Plan 覆盖 | 两业务必需 13 块、三业务必需 15 块；遗漏块、错误业务 ID、依赖环和不合法期间能被检出并定向修复 |
| 上下文 | 小上下文配置下仍通过批次完成；不把无关业务原文传给财务块；保留表头、比较列及脚注；选择过程可追溯 |
| 截断恢复 | 注入长度截断后缩小/拆分请求；不接受不完整 JSON；不无限重试；其它已校验块可复用 |
| 同比基本值 | 500→550 为 +50、+10%；100→80 为 −20、−20%；计算和展示单位一致 |
| 特殊基数 | 利润 40→−10 为 −50、−125% 且注明转亏；−100→−60 为亏损收窄 40，不写同比增长 −40%；0→10 不适用百分比、增减额 +10 |
| 比率与期间 | 30%→32% 为 +2 个百分点；中期对上年同期，较上年末独立标注；单季度和累计不能混用 |
| 核心硬门槛 | 缺核心同期值、最早年度基数、错归母口径，或有表无必要正文时，终审不通过；耗尽补查后 blocked |
| 证据及重述 | 最新重述替换可比值并保留版本；旧计算、正文及终审失效；重大冲突未解决不能交付 |
| 报告一致性 | 核心观点、五个财务小节、业务章、三表及三种导出使用同一快照数字，引用可解析 |
| 局部返工 | 修改一个业务事实只重跑依赖内容；不能继续使用受影响的旧核心观点或审核通过记录 |
| 预算和故障 | 限流、超时、无证据、耗尽预算和恢复均有限且可诊断；界面状态与实际任务一致 |
| 历史复用 | 已校验且口径一致的历史数据复用；新增披露补入；重述触发下游更新；记录真实 token 变化 |

实施验收顺序：确定性规则与 fixture → Mock 全流程及故障注入 → 双协议与恢复 → 在线阅读及导出 → 真实模型代表性研究。真实验收至少覆盖两业务公司、三业务以上公司，以及负利润或经营现金流负基数场景；使用可追溯真实披露，记录模型配置、截断、遗漏、返工、调用数、输入/输出 token、用时和最终状态。

同一数据集和研究范围下比较现有架构与拆分架构，优先评估必需覆盖率、核心同比合格率、可交付率和总成本。不以 Mock 成功证明真实模型胜任，也不以某次失败直接推断模型参数量不足。
