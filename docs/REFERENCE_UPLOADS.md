# 启动页参考资料上传

已实现启动页多文件上传、解析状态与错误提示、移除待提交文件、创建研究时绑定附件、任务刷新后的附件列表，以及真实研究的参考资料优先提取和缺失项检索。

在公司名称下方的“参考资料”区域点击“添加文件”，选择年报、研报或其它材料。文件显示“已解析”后点击“开始研究”，系统将选中的附件原子绑定到新任务，首次研究取数前即可读取全部资料。上传或解析过程中不能提交研究；提交失败保留已上传的文件，可以重试。

支持 PDF、DOCX、XLSX、CSV、TXT、Markdown、JSON、HTML，默认单文件最多 20 MiB、每项研究最多 50 份，可通过 CDR_REFERENCE_MAX_FILES 配置为 1–200 份，前端同步显示后端上限。扫描 PDF 需要先提供 OCR 后可读取文字的版本；损坏、空文件及无正文文件会明确提示，不能伪装为上传成功。移除待提交文件表示本次研究不绑定该附件，原暂存文件保留。

真实研究中：

- 用户上传资料优先于自动收集的资料，不因原文件是券商研报而降级。
- 首先从附件确认公司身份、规划期间与业务，并提取完整参考资料。若附件无法确认上市主体，只补查主体身份。
- 财务需求按公司、指标、期间、单位、合并/分部范围及实际/预测匹配；研究问题要求引用已经提取的上传证据。已覆盖需求不会继续执行原来的全量查询，外部查询只包含缺失的字段或问题。
- 行业报告采用独立的背景资料提取：行业规模、供需、政策、竞争格局、产业链、技术及经营信息作为有原文依据的研究证据，进入对应的行业/业务分析和写作。相关材料不要求逐字包含公司或具体业务名称；保留年份、地域及统计口径，不当作目标公司的财务事实。
- 多份附件同字段冲突时保留上传资料冲突，由人工选择上传候选；不调用外部来源裁决。
- 所有原始候选保留；计算、正文使用有效裁决数据。附件和覆盖记录纳入阶段成果导出，原文件哈希纳入续跑兼容性校验。

模拟模式只保存并展示附件，不把用户真实材料混入合成演示数据；真实资料的优先提取需要真实模式。研究过程中新增/替换附件和完整的人工直接录入权限仍属于后续设计，不是本次启动页上传实现。

## 已实现接口

| 方法与路径 | 用途 |
|---|---|
| `POST /api/reference-attachments?filename=...` | 请求体为文件原始二进制，返回附件 ID、文件名、大小、哈希、解析状态和片段数量 |
| `POST /api/research` | 请求 `{company, attachment_ids?: string[]}`，原子校验附件、创建任务并绑定后排队 |
| `GET /api/research/{run_id}/attachments` | 返回本任务附件列表和字段/问题覆盖记录 |

附件只能绑定一个任务；其它任务必须重新上传，不能读取或采用已有任务的材料。存储位置为数据库目录下的 `reference_uploads`，不进入共享 `data/local_sources` 检索目录。路径和完整文件正文不在上传响应中返回。

前端开发服务可以热更新；已启动的后端需要重新加载，才会出现上传 API。正常关闭启动窗口后重新运行项目根目录的 `start.bat` 即可加载全部新代码。
