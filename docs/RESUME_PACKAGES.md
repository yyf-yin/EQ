# 成果包导出与上传续做

日期：2026-10-19。

目标：把一次研究里已经完成的资料、数据、计算和合格章节导出成文件；下次上传这个文件，新建任务时跳过沿用的部分，只做没完成或不合格的工作。原来的断点续跑会因提示词、模型、资料变化或质量阻断而整体拒绝，导致没有问题的工作也要重做。

## 1. 与断点续跑的关系

| | 断点续跑（原有） | 成果包续做（本功能） |
| --- | --- | --- |
| 任务 | 沿用原 run_id | 新建 run_id，原任务不变 |
| 触发 | 页面继续（重启后限最近未完成任务） | 用户上传成果包并确认 |
| 提示词/模型/资料变化 | 拒绝 | 列出风险，用户确认后照样沿用 |
| 终审质量阻断 | 拒绝，只能新建研究 | 只丢弃不合格章节，或从指定阶段重做 |
| 粒度 | 工作单元 | 阶段 + 章节 |

原断点续跑仍保留，用于暂停、断网、进程崩溃等配置没变的情况。

## 2. 成果包内容

ZIP 文件，接口 `GET /api/research/{id}/resume-package`。只能对已停止的任务（failed/blocked/interrupted/waiting_human/completed/limited）导出，并且要求有当前规则版本的业务检查点、通过数据隔离检查。

| 路径 | 内容 |
| --- | --- |
| `package.json` | 格式版本、来源任务、导出时的执行指纹（提示词/模型/资料/规则摘要）、检查点节点、可沿用阶段与建议、章节审核状态、其它文件的 sha256 清单 |
| `state/context.json` | 最后完成节点之后的完整研究上下文 |
| `state/records.json` | 来源、证据、事实、数据槽、计算、块分析等业务记录（不含调用、用量、批准、审核记录和章节写作缓存） |
| `attachments/` | 本次上传的年报与参考资料原文件及解析结果 |
| `readable/summary.md`、`readable/draft.md` | 给人读的评估摘要与章节草稿 |

上传时逐个核对清单里的 sha256，包里有清单外的文件、缺文件或内容不符都会被拒绝。这只防止文件损坏或误改，不防止故意重算哈希的修改；导入后的成果仍然要经过确定性检查和终审。

## 3. 可沿用的阶段

| 级别 | 沿用内容 | 新任务从这里开始 | 需要原任务至少完成 |
| --- | --- | --- | --- |
| `collection` | 公司识别、研究规划、资料与数据收集 | 财务分析 | 数据缺口检查 |
| `forecast` | 以上 + 财务分析、盈利预测与复算 | 分块分析 | 复算 |
| `blocks` | 以上 + 分块分析 | 章节写作（全部重写） | 分块分析 |
| `writing` | 以上 + 选定的合格章节 | 章节写作（只写未沿用的章节） | 报告组装 |

沿用级别越高，后面的阶段越少。依赖关系按阶段处理：选了某一级，它之后的阶段一律重做，不会把旧的下游结果与新的上游结果拼在一起。`collection` 和 `forecast` 级别会丢弃旧块分析；低于 `writing` 时不沿用任何章节。

章节状态取自上下文中报告当前快照的终审记录：
- `failed`：有 error/critical 问题，或最后一轮遗留未解决的意见。默认不沿用。
- `passed`：已审核，没有上述问题。默认沿用。
- `unreviewed`：还没审核到。默认沿用，新任务会对它重新审核。

核心观点依赖全部章节，只要有任何章节重写，它就跟着重写。toc/三表/免责声明是确定性生成的，不在可选列表里。

建议级别由不合格问题指向的返工节点决定：
- 指向财务分析、预测假设或计算的，建议 `collection`（从财务分析起重做）。
- 指向资料收集或研究规划的，成果包无法只重做收集，提示建议新建研究，同时给出最低级别 `collection`。
- 写作问题建议 `writing`，并默认丢弃对应章节；有写作问题定位不到具体章节时，建议 `blocks`（全部章节重写）。

建议只是默认选项，用户可以改选其它已完成的级别。

## 4. 风险确认

上传后先检查（`POST /api/resume-packages`），返回 package_id、来源信息、可选级别、章节列表和风险清单。风险是导出时的执行指纹与当前配置的差异：

| 差异 | 风险 |
| --- | --- |
| 提示词 | 沿用成果按旧提示词生成，口径可能与新提示词不一致 |
| 模型配置 | 沿用成果来自其它模型或参数 |
| 本地资料目录 | 沿用的收集结果基于旧资料，新增/删除的资料不会体现 |
| 数据采集规则/槽位模板 | 沿用数据可能缺少新字段或口径不同（高风险） |
| 财务核对规则、执行规则版本 | 沿用的数据或计算可能不满足新规则（高风险） |
| 研究限额、检索服务、人工核验规则 | 低风险 |

有风险时必须带 `accept_risks=true` 才能导入。业务规则版本（`rules_version`）不同或运行模式（模拟/真实）不同是不兼容，不能导入。提示词或模型变了时不沿用终审语义审核缓存，未改动的章节也要重新审核。

## 5. 导入

`POST /api/resume-packages/{package_id}/import`，参数为 `level`、`keep_sections`（仅 `writing` 有效）和 `accept_risks`。

1. 新建任务，重新登记包内附件（新 attachment_id），写入隔离标记、启动会话、吞吐策略和 `resume-package` 来源记录（包哈希、来源任务、级别、沿用/丢弃章节、已确认风险）。
2. 写入业务记录，把上下文和记录里的旧 run_id 替换为新 run_id；修订计数、审核问题和核心观点修订指令清零，所以新任务有完整的返工轮次和预算。
3. 在新任务的图线程上以对应前驱节点写入上下文，检查下一节点是否就是预期入口，不是就整体回滚。
4. 为沿用的阶段写入“沿用成果包”进度事件，然后排队执行。

被沿用的数据与原任务一样属于本任务的输入，交付前照常经过终审、核心同比、快照批准等门槛。数据隔离规则相应调整：隔离仍禁止程序自动跨任务取用历史资料；用户显式上传的成果包允许使用，并记录来源包哈希供追溯。

## 6. 暂不覆盖

- 阶段内部的部分进度（例如 15 个研究任务完成 12 个）不进包；这种情况用原断点续跑。
- 不支持编辑包内容后再导入。
- 只沿用到“数据收集完成”为止的最低级别；只保留研究规划没有意义，直接新建研究即可。
