# 上传参考资料、数据来源优先级与人工确认权限改进设计

状态：总体设计方案。启动页上传、任务附件绑定、参考资料优先提取和缺失项检索已实施，实际接口与范围见 [启动页参考资料上传](REFERENCE_UPLOADS.md)。运行中附件变更、独立财务接口接入和完整人工直接录入权限等仍为设计内容。适用于真实研究；模拟模式保留明确的模拟标识。

## 1. 核心规则

1. 人类提交的信息视为已经审核的真实信息。人工可以直接输入、修正具体财务数值，不要求提供年报、链接或原文摘录，也不要求再次通过原始披露证明。
2. 有效数据的最终采用优先级为：**用户上传参考资料 > 人工确认 > 财务数据接口与公司官方报告 > 其它来源**。用户上传的年报、研报及其它参考资料均为最高层，不因其原始发布渠道降级。人工可选择上传材料中的冲突值或纠正提取错误，具体操作绑定该材料与字段，作为参考资料裁决生效。
3. 上传参考资料能明确提供的数据，只从参考资料获取；不再对这些字段发起接口、官方报告或其它搜索，也不为了外部交叉验证重复取数。先完成参考资料覆盖检查，后续仅获取缺失字段。
4. 接口与官方报告属于同一权威层。它们可以立即覆盖其它渠道的有效值，不需要先完成冲突补查，更不因其它渠道数量多而转为人工复核。
5. 接口和官方报告出现无法自动解释的真实冲突，先自动刷新接口、查报告版本与更正信息，仍无法确定时才请求人工；人工直接输入即可解决。
6. “覆盖”指替换有效输入、引用和依赖快照；所有原始材料、候选和旧裁决保留，供追溯。
7. 覆盖只作用于同一公司、指标、期间和口径。不同期间、币种、合并范围或实际/预测数据不得互相替换。

## 2. 当前实现与问题

以下为当前代码可确认的限制，不代表已定位某个具体运行任务的全部原因。

- `datasources.py / UnifiedDatasource.retrieve` 目前合并本地检索和网页搜索，没有专用财务数据接口，也没有保证官方报告先于其它网页获取的取数阶段。搜索 API 是搜索渠道，不等于权威财务接口。
- `reconciliation.py / primary_proof` 只识别交易所和巨潮域名，尚未识别经验证的公司官网；对连续原文中的单年度、期间、单位和数字要求很窄，容易漏掉有跨页表头、多年列的年报、半年报和季报。
- `reconcile` 在候选一致时直接按事实 ID 取第一条，没有优先保留权威引用；候选冲突时，通常还需要 `checked_groups` 才能采用原始披露。其它来源的会计口径差异也可能阻止权威候选被采用。
- `human_intervention.py / refresh` 会在采集期间发布人工核验待办；此时权威取数可能尚未完成。
- 人工目前只能选有原始披露证明的候选，或者基于已收集来源补充原文，不能直接录入已审核数据。已进入计算的待办还会限制提交。
- 当前人工裁决绑定候选集合，新候选出现可能使人工反馈失效，不符合“人工已审核的信息应直接有效”的要求。
- 创建任务 API 目前仅接收公司名称，没有上传、附件绑定和任务内参考资料索引。共享 `data/local_sources` 目录不能替代按任务上传功能，也不应自动取得用户上传的最高优先级。

## 3. 来源模型：渠道、权威性和校验状态分开

`kind=web/local/api/manual/upload` 描述获取渠道；用户明确上传并绑定本任务的参考资料由服务端登记为最高优先级，自动扫描的本地文件仍按原始来源分类。

| 权威层 | 分类 | 可采用条件 | 覆盖规则 |
|---|---|---|---|
| R | `uploaded_reference` | 用户上传并绑定本任务，提取值与目标字段匹配 | 覆盖 H/A/B；已覆盖字段停止其它渠道取数 |
| H | `human_confirmed` | 人工提交成功，字段和格式合法 | 覆盖 A/B；不自动覆盖 R；保持有效直到人工修订或撤销 |
| A | `financial_api` | 已配置并认可的财务接口；响应字段、主体、期间、单位和口径匹配 | 覆盖 B；不能覆盖 H |
| A | `official_report` | 交易所/披露平台发布的公司报告，或经验证的发行人官网报告；字段可定位 | 覆盖 B；不能覆盖 H |
| B | `secondary` / `unknown` | 自动获取的媒体、研报、转载、一般网页、无法证明出处的本地资料等 | 只作补充候选；不能覆盖 R/H/A |

公司年报、半年报、季报及针对相关指标的正式更正公告均属于 A。报告类型按目标期间选择，不设置“任何年报都压过任何季报”的排序。

财务接口必须经过适配器配置和字段合同校验。网页搜索接口、模型接口、任意 JSON 地址不会因使用 API 就升为 A。经认证的本地官方报告副本可保持 A；仅文件名包含“年报”不能证明官方身份。用户上传并绑定的参考文件按 R 处理，人工直接录入数据或文本按 H 处理；资料目录中自动扫描出的文件仍按可证明的来源分类。

建议扩展字段：

- SourceRecord：`authority_class`、`authority_verified`、`provider_id`、`issuer_id`、`report_type`、`document_id`、`report_period`、`revision_id`、`authority_evidence`、`attachment_id`、`reference_set_version`。
- EvidenceRecord：`validation_method=source_quote/api_field/human_confirmation/uploaded_reference`；接口保存响应位置，人工保存确认记录引用，上传材料保存文件及页/表/行列位置。
- RequiredData：增加 `scope`、`currency`、`accounting_basis`，以及规范的期间起止日、期间类型；人工待办继承这些字段。
- FinancialFact：保留统一数值与证据模型，增加 `authority_class`、`confirmation_id` 和明确的期间口径；权威等级由服务端确认，模型不得自行指定。
- HumanConfirmation：保存 `confirmation_id`、`identity`、数值、单位、会计口径、确认人、确认时间、修订号、可选说明与可选附件、生效/撤销状态。
- ReferenceAttachment：保存 `attachment_id`、所属草稿/任务、原文件名、存储位置、内容哈希、文件类型、上传时间、解析状态、启用状态、材料版本和可选排序。
- ReferenceCoverage：保存需求/研究问题、参考资料版本、覆盖状态、选用事实/证据、位置及缺失原因；状态为 `pending/covered/absent/ambiguous/unparseable`。

人工记录不伪造成原始公告证据。它以 `human_confirmation` 方式满足正式计算与交付的证据要求，引用显示“人工确认”。

## 4. 取数顺序与覆盖检查

以每个 RequiredData 的目标字段为单位，而不是只对搜索结果排序：

```text
上传参考资料解析与覆盖检查
  ├─ covered：直接采用，停止该字段所有外部取数
  ├─ pending：等待提取完成，不提前搜索
  ├─ ambiguous/unparseable：先处理参考资料问题
  └─ absent：人工确认 → 财务接口 → 对应期间官方报告 → 其它渠道
```

1. 先查 R 层，参考资料覆盖的字段直接满足需求，包括历史财务、经营信息、行业数据及预测假设依据。参考资料存在但尚未完成提取时，不提前请求外部来源。
2. R 层明确缺失的字段，有 H 值则直接采用；没有 H 时，调用适用、已配置的财务接口。接口返回有效值即可满足需求，不要求“另有年报”才能使用。
3. 接口缺字段、调用失败、口径不明，或者已经发现 A 内部冲突时，优先查交易所/披露平台及已验证公司官网。报告背景等独立任务也先检查参考资料，仅检索其未覆盖的问题；不得以“补充核验”名义重新获取参考资料已有的数据。
4. 年度流量指标查年报；半年累计查半年报；季度区分单季与年初至季末累计；资产负债表查目标截止日。不同期间的补查任务不得一律拼“年报”。
5. 官方检索优先获得报告目录、全文链接、报告 ID 和对应期间。第三方转载可用于发现官方链接，但转载本身仍为 B。
6. 每项权威探测保存 receipt：路径、身份、覆盖字段、报告 ID、结果和重试情况。结果区分 `success/not_found/not_configured/failed/unparseable`，技术失败不描述成“公司未披露”。
7. 只有 R 层明确缺失且适用权威取数路径已经完成有界尝试，仍无有效 H/A 数据，才将关键字段转为人工待办；参考资料自身的冲突或解析问题按第 11 节处理，不用外部数据消解。

接口批量取数、单份报告多字段提取、请求缓存及有界重试复用现有执行账本。失败路径只消耗已配置预算，不无限补查；未配置接口不作为永久等待条件。

## 5. 规范化与自动裁决

### 5.1 字段身份

推荐身份包含：公司、指标、期间起止日、期间类型、合并/母公司/分部范围、分部、实际/预测、币种、会计口径。单位统一后比较 Decimal 值，保留原始单位和原值。

会计口径分开匹配需求，避免其它来源的“调整后”值使已有权威“报告口径”值失效。追溯重述等口径转换必须有明确的版本关系，才允许替换需求中的旧报告值。接口声明的 latest/restated 也须有字段合同和版本依据。

半年累计、前三季度累计、单季度、全年不能因为年份一致而混用；归母净利润与净利润、扣非与非扣非不能当作同指标。禁止以未知币种或范围的候选默默补齐关键数据。

### 5.2 决策表

| 同一目标字段的候选情况 | 采用结果 | 人工处理 |
|---|---|---|
| 上传参考资料明确提供目标字段 | 采用 R；不发起该字段的外部取数，不因原材料是研报而降级 | 无需外部真实性复核 |
| 多份上传材料提供同字段同值 | 合并依据，采用稳定引用 | 无需复核 |
| 多份上传材料同字段不同值，无明确版本或人工指定 | 保留 R 冲突，不降到接口或其它来源选数 | 人工选择材料或修正字段 |
| 有当前有效人工确认 | 采用 H，所有自动候选仅保留 | 无需重复复核 |
| 只有一个有效 A，B 数值不同或很多 | 立即采用 A，B 标为未采用 | 不产生人工待办 |
| A 与 B 一致 | 采用 A 的数值与引用 | 不产生人工待办 |
| API 与官方报告同值、同口径、同版本 | 采用统一值，保留两者依据；有报告时优先展示报告引用 | 不产生人工待办 |
| 多个 A 不同，但可证明接口版本陈旧或有明确更正关系 | 采用已证明的新版本，记录替换关系 | 自动解决 |
| 多个 A 不同，刷新和版本检查后仍无法确认 | 自动值暂不进入该字段计算 | 产生“权威数据冲突”待办；可直接输入 |
| A 文件可信，但字段解析或单位/期间无法确认 | 先尝试结构化提取和定向补查 | 耗尽后产生“字段解析失败”待办 |
| 无 H/A，只有一个或多个 B | 保留临时候选，继续权威取数 | 关键字段耗尽后待人工确认；非关键字段保留限制 |
| 人工确认格式非法或字段身份不完整 | 在提交界面提示修正，尚未落为有效值 | 不要求来源证明 |

“同值”默认精确比较规范化后的 Decimal。不同披露精度只有在接口/报告明确提供精度、且区间一致时才可标为精度等价；采用完整精度值并记录依据，禁止以任意百分比容差消除真实差异。

人工录入字段可由待办预填，也可通过独立的“录入数据”入口创建。机器侧的必填、数字格式、有限数、单位、主体与期间检查只是确保数据可计算，不构成再次审核其真实性。允许录入 0、负数与完整精度，不自动改变符号或数值。

伪代码：

```python
def decide(requirement, references, candidates, confirmations, authority_receipts):
    coverage = reference_coverage_for(requirement, references)
    if coverage.status == "pending":
        return wait_for_reference_extraction()
    if coverage.status == "covered":
        return selected(coverage.fact, rule="reference-first", forbid_external=True)
    if coverage.status in {"ambiguous", "unparseable"}:
        return reference_resolution(requirement, forbid_external=True)

    human = active_confirmation_for(requirement, confirmations)
    if human:
        return selected(human, rule="human-confirmed")

    compatible = normalize_and_match(requirement, candidates)
    authoritative = verified_authoritative_fields(compatible)
    if authoritative:
        resolved = resolve_document_revisions(authoritative)
        if same_value_and_basis(resolved):
            return selected(preferred_reference(resolved), rule="authority-over-secondary")
        if not authority_checks_exhausted(authority_receipts):
            return auto_check(reason="authority-conflict")
        return needs_human(reason="authority-conflict")

    if not authority_paths_finished(authority_receipts):
        return auto_collect(reason="authority-not-yet-collected")
    if is_critical(requirement):
        return needs_human(reason="missing-or-unparseable-authoritative-data")
    return limitation(provisional_candidates=compatible)
```

A 层冲突不能仅按抓取时间、标题、网页日期或候选多数决定。版本和更正关系已明确时自动解决；其它情况由有直接录入权限的人工确认解决。

## 6. 报告和接口验证方式

- 上传参考资料：按用户指定的 R 层采用，不重复验证发布渠道。仍须定位提取值的页码、表格或段落，确定主体、期间、单位和实际/预测类型；这个步骤是提取准确性检查，不是重新审核用户材料的真实性。
- 官方报告：验证发行人身份、发布渠道、报告期间及文件来源。公司官网通过上市主体资料或官方披露中的官网信息建立登记，不能凭域名名称猜测身份。
- 表格字段：保留页面、表格、行、列、单位表头、年度/期间列头和必要脚注。允许多年度表，根据列位置确定目标值；不再要求所有信息挤在一段单年度连续原文里。
- 财务接口：保留原始响应哈希、提供方、接口合同版本、请求时间、返回的报告期与版本、JSONPath/字段位置、原值和原单位。结构化响应不强制满足自然语言“年报摘录”的正则。
- 人工确认：确认记录本身是审核依据，无需 `primary_proof`、链接、原文或更正前后证明。说明和附件均可选。
- 来源身份可信不等于任意抽出的数字都可用。自动候选仍需要字段匹配与提取验证；人工确认则以提交人给定的字段和值直接有效。

## 7. 人工权限与待办生命周期

### 7.1 直接录入权限

待办提供“直接输入已审核数据”“采用候选并确认”“补充资料/补查”三个操作。另提供独立录入入口，不要求先出现冲突或缺口。

必填为目标身份、数值和单位；身份从待办预填并可修正。提交时显示“提交后作为已审核真实数据采用”。确认人和时间自动记录；当前单用户系统可使用本地操作者身份，不因此新增账户系统。

- `confirm_value`：直接创建 H 事实，填补缺失或覆盖 A/B；不再运行原始披露真实性检查。有 R 值时默认保持参考资料优先；如用户主动纠正参考资料字段，使用 `correct_reference_value` 并绑定对应材料，记录为 R 层人工修正，不静默覆盖原文。
- `confirm_candidate`：将选中的具体值和完整身份复制为新的 H 事实，保留原候选引用；选 B 或解决两个 A 的矛盾也可直接生效。
- `revise_confirmation`：生成新人工版本，旧版本保留并失效；采用最新有效人工修订。
- `revoke_confirmation`：明确撤销人工覆盖，重新采用自动裁决结果；可能重新出现权威冲突或缺失待办。
- `select_reference` / `correct_reference_value`：选择上传材料中的候选或纠正其提取值，形成绑定材料与字段的 R 层裁决，仍然最高优先级。支持撤销修正并回到材料提取结果，不要求额外原文真实性证明。
- 人工上传并绑定材料登记为 `uploaded_reference`；直接提供说明登记为 `human_confirmed`。财务数字须绑定明确字段才能进入计算，无法解析时提示补充字段。

### 7.2 何时发布待办

采集中的机器差异记入取证状态，不直接显示“请人工复核”。状态顺序为 `indexing_reference → checking_reference_coverage → resolved / collecting_authority / reference_needs_input`；只有参考资料明确缺失，才继续 `collecting_authority → auto_checking → resolved / needs_human`。

只在自动取数和裁决走完后发布实际待办，给出明确类型：权威缺失、权威冲突、报告字段无法解析。待办显示接口与报告的尝试结果，包含未配置、未找到、网络失败或解析失败，避免“只有媒体、没有尝试年报”的不透明状态。

新增权威候选或人工确认自动解决待办时立即关闭；其他独立研究继续。关键待办未解决时沿用 `waiting_human` 释放执行名额。

### 7.3 人工确认不因机器候选变化失效

人工确认绑定目标字段及人工修订号，不绑定自动候选集合。后续抓取、换报告、增加转载，都不能使已确认值失效或重开同一字段的阻断待办。新官方数字与 H 不同，只增加审计差异，由人工主动修订或撤销后再改值。

提交并发采用人工修订号的原子比较及请求幂等键；自动候选更新不应导致“版本过期，无法提交”。若另一次人工修改已生效，提示当前人工版本，防止互相覆盖。已自动解决的待办仍允许通过独立录入入口覆盖其字段。

### 7.4 计算开始后也可修正

取消“进入计算后人工只能只读”的权限限制。人工可提交新值；系统原子保存确认并生成下一输入快照，旧快照上的在途计算可以结束保存，但不得写入新快照或获得正式交付资格。

由依赖图重新排队受影响计算、同比、预测、分析与写作。重新生成和审核后交付新版报告。已完成报告保留旧版及其人工修改记录，不在后台静默改写旧文件。主动暂停的任务可保存修改，但继续执行仍遵守用户暂停状态。

## 8. 裁决、重算、报告和审计

FactDecision 建议保存：`selected_ids`、`selected_authority`、`rule`、`reason`、`ignored_ids`、`ignored_reasons`、`confirmation_id`、`attachment_ids`、`reference_set_version`、`reference_coverage_id`、`external_fetch_allowed`、`authority_receipt_ids`、`input_snapshot_id`、策略版本。

规则示例为 `reference-first`、`reference-human-correction`、`reference-conflict`、`human-confirmed`、`authority-over-secondary`、`authority-equivalent`、`explicit-revision`、`authority-conflict`、`authority-missing`。未采用材料显示“已被上传参考资料/人工确认/官方报告/接口覆盖”，而不是继续显示未解决冲突。

有效值、口径或采用引用变化，沿用现有依赖失效机制。若只增加未采用的 B 来源，决策审计可以更新，但有效输入快照不变、计算不失效、人工确认不失效。纯引用变化可复用数值计算，更新引用和文稿；数值或口径变化才重算数字。

计算输入、假设依据、研究摘要和正式写作都采用当前有效事实；历史摘要中未采用的数字也要过滤或重建，防止“计算已用参考资料数，正文仍沿用外部数”。事实审核与最终审核接受 `uploaded_reference/human_confirmation/api_field/source_quote` 四种证明方式，不能在待办或提取层放行后，终审又要求补充年报或外部来源。

人工记录、接口响应定位、官方报告链接及裁决记录进入阶段成果和评估包。人工确认值显示“已人工审核”，可查看确认人、时间和修订历史；不再显示为“待核实”。

## 9. 工程改动位置与实施顺序

1. `schemas.py`：扩展上传附件、参考资料覆盖表、来源/事实/证据权威字段、精确需求身份和人工确认模型。区分内容提取成功与最终采用权限。
2. `api.py`、`storage.py`、`config.py`、前端 `App.tsx`、`api.ts`：新增草稿附件上传、绑定任务、附件列表、禁用/删除/替换和上传状态，按任务隔离存储；第 11 节定义接口。
3. `datasources.py`、`researcher.py`、`graphs.py`、`planners.py`：参考资料优先解析与提取，覆盖表生成并裁剪检索任务；新增财务接口适配器、官方报告路由、按期间选择查询、权威覆盖 receipt，继续复用当前任务内缓存及有界执行。
4. `reconciliation.py`：R 优先、H 次之，A 立即覆盖 B；拆分参考资料冲突、自动冲突与真正需要人工的状态，替换宽泛的 `checked_groups` 前置要求。
5. `human_intervention.py`、`api.py`、`storage.py`：实现直接输入、确认候选、修订、撤销及独立录入接口；提交 H 值直接生效，支持 R 层选择与纠正，不调用 `primary_proof` 或 `correction_proof` 限制人工权限。
6. `graphs.py`、`reviewers.py`、`evidence.py`、`writers.py`：接受参考资料、人工确认和结构化接口证据；统一计算、上下文和正式交付门槛，处理输入快照变化与计算后修正。
7. `work_products.py`、前端 `HumanInterventionView.tsx`、`types.ts`：展示取数进度、采用等级、参考资料覆盖/缺失、跳过外部取数原因、人工录入与历史，不把机器差异提前当成人工任务。
8. `execution.py`、恢复逻辑和说明文档：上传文件哈希、附件启用状态、参考资料版本和采用规则进入输入快照与恢复校验；升级来源及人工策略版本，恢复前重做采用裁决。已有人工确认按 H 迁移，不因没有年报证明降级；未明确绑定的历史本地材料不自动升为 R。

设计不指定某个外部财务接口提供方，也不虚构现有 API 已接通。适配器、合同、字段覆盖和权限配置随实施接入；未配置时直接走官方报告路径。

## 10. 验收用例

| 场景 | 应有结果 |
|---|---|
| 上传研报收入 110，已有接口 120、人工确认 130 | 采用 R 值 110，保留旧候选；不再获取该字段 |
| 上传年报提供收入和净利润、没有现金流 | 收入/净利润不产生外部请求，只补现金流 |
| 上传材料覆盖全部财务和研究问题 | 财务 API 与网页搜索调用为零；仍可调用模型提取和分析 |
| 参考资料提取中或解析队列尚未结束 | 不抢先调用外部来源 |
| 两份参考资料同字段不同值 | 要求选择材料或修正提取，不转用接口裁决 |
| 上传研报只有未来盈利预测，目标是历史实际收入 | 不把预测值当历史值；只补缺失历史字段 |
| 资料覆盖公司业务问题，但缺行业规模 | 公司业务不再检索，只补行业规模 |
| 上传扫描 PDF 提取失败 | 显示解析问题，支持替换/手工录入；不静默降级搜网 |
| 任务 A 上传材料，任务 B 未上传 | B 不读取 A 附件，不能因内容哈希相同跨任务引用 |
| 运行中上传资料覆盖原待办或排队取数 | 原待办自动解决，未发请求取消，新输入触发局部重算 |
| 禁用/替换附件后暂停并续跑 | 重新检查覆盖；只补新增缺口，保留其它执行成果 |
| 媒体收入 100，年报收入 120 | 自动采用 120，媒体保留，无人工待办 |
| 多家转载 100，接口 120 | 自动采用 120，不多数票；无年报也可用 |
| 同值媒体候选 ID 比报告更靠前 | 采用权威引用，不受 ID 排序影响 |
| 人工直接输入收入 130，未提供链接 | 按已审核真实数据采用 130，通过计算和终审 |
| 人工选择媒体候选 100 并确认 | 创建 H 值 100，覆盖接口/报告，无再次来源证明要求 |
| 人工已确认 130，随后官方更正为 140 | H 仍为 130；记录差异，不失效、不重开阻断待办 |
| 人工修订 130 为 140 | 新人工版本生效，仅重算受影响依赖 |
| 人工撤销覆盖，API/报告均为 120 | 回到 120，保留原人工版本和撤销记录 |
| 接口 120、报告 125，证明接口仍为更正前版本 | 自动采用更正后 125 |
| 接口 120、报告 125，无版本依据，自动检查耗尽 | 权威冲突待办；人工可直接给出最终值 |
| 年报多年度表，单位在表头 | 按行列和表头定位采用目标年度；不因多个年份出现而拒绝 |
| 半年报累计数与季度单季数 | 分开识别期间；不互相覆盖、不误报数值冲突 |
| 只有媒体 100，官方尚在获取 | 显示自动取数中，不提前要求人工复核 |
| 只有媒体 100，适用权威路径已耗尽 | 关键字段请求人工直接输入/确认；非关键字段保留限制 |
| 公司官网报告经身份登记验证 | 属于 A；伪官网、一般搜索 API 或仅改文件名仍为 B |
| 人工提交期间自动候选增加 | 提交正常生效；只有另一人工修订冲突才提示版本变化 |
| 已在计算或报告完成后人工录入新值 | 保存新快照、重算并重新审核，新版交付；旧版保留 |
| 新增未采用转载，或暂停/续跑 | 不使有效输入重算、不使人工确认失效；保持任务隔离 |

实施测试应覆盖从录入到计算、上下文、终审、导出和续跑的整条链路，避免出现“人工页面成功，后续仍按低权限处理”的假成功。

## 11. 上传参考资料功能

### 11.1 页面与上传流程

创建研究时，在公司输入旁提供“上传参考资料”，支持多份年报、半年报、季报、券商研报、行业报告及其它材料。优先复用现有 PDF、DOCX、XLSX、CSV、TXT、Markdown、JSON、HTML 解析器；单文件默认沿用 20 MiB 上限，每项研究默认最多 50 份，数量可配置为 1–200 份。界面显示支持格式与上限。

文件先上传至研究草稿，返回附件 ID、文件名、大小和解析状态。创建研究提交 `company` 与 `attachment_ids`；任务启动前原子绑定附件集合，保证首次取数前知道全部资料，不出现“先搜网、再收到年报”。解析使用本地解析器，模型只做内容提取，不把文件内容交给搜索接口。

任务进度页提供“参考资料”面板：上传新资料、查看解析进度、预览原文、显示已采用数据与位置、查看未覆盖项、选择冲突材料、纠正字段、禁用或移除资料。状态包括上传中、解析中、提取中、可用、部分可用、解析失败、停用。

### 11.2 建议接口与存储

以下是拟新增合同，不是已实现接口。

| 接口 | 功能 |
|---|---|
| `POST /api/reference-drafts` | 创建上传草稿，获得 draft_id |
| `POST /api/reference-drafts/{draft_id}/attachments` | multipart 上传，返回 attachment_id 和解析状态 |
| `POST /api/research` | 新增可选 draft_id、attachment_ids；校验并原子绑定后启动 |
| `POST /api/research/{run_id}/attachments` | 运行中新增附件，更新参考资料版本 |
| `GET /api/research/{run_id}/attachments` | 附件、状态、覆盖汇总与版本列表 |
| `GET /api/research/{run_id}/attachments/{attachment_id}/preview` | 分页原文和证据位置预览 |
| `POST /api/research/{run_id}/attachments/{attachment_id}/state` | 启用、禁用、移除或指定替换附件；保留审计 |
| `GET /api/research/{run_id}/reference-coverage` | 已覆盖数据/问题、待解析项、缺失项和外部取数许可 |

草稿及研究附件分别保存在 `data/uploads/drafts/{draft_id}/`、`data/uploads/runs/{run_id}/`，真实存储名由系统生成，原文件名只用于展示。类型、大小和解析错误沿用现有文件读取约束；附件不得进入共享本地检索目录。内容哈希用于同任务去重与恢复校验，不授权跨任务复用。移除附件先禁用并保留旧快照引用，当前研究失去覆盖后重新规划；物理清理只处理无有效引用的文件。

### 11.3 覆盖驱动的调度约束

1. 身份解析和研究范围规划首先读取上传资料；如果目标公司身份仍不明确，单独补查身份，不顺带抓取已覆盖财务字段。
2. 规划确定需求后，对全部启用资料提取并生成 ReferenceCoverage。每个待检索字段/问题在调度前都必须检查当前覆盖版本；粗略关键词匹配不是“已经获取”。
3. `covered` 不创建 search、API 或定向补查任务；混合任务剔除已覆盖字段/问题，只保留 `absent` 部分。不能只改变最终选数而继续执行原来的全量搜索。
4. `pending` 等待对应资料处理；`ambiguous` 和 `unparseable` 先请求选择材料、手工修正或替换。用户可主动禁用无法使用的资料，此后重新评估缺口并走后续路径；系统不静默改用外部来源。
5. 批量财务接口优先请求缺失字段。若响应不可避免带回其它字段，这些附带值不提取、不作为候选、不进入引用；已覆盖整个请求目标时跳过请求。后续搜索同样只针对未覆盖的问题。
6. 通用研究问题按问题/事实检查覆盖，不能因上传了任何一份年报就宣布整个公司或行业已覆盖，也不能因只缺一个行业问题而重搜已覆盖业务资料。
7. 引用最高优先级资料时仍区分历史事实、预测、假设和观点。研报预测只能进入对应预测/假设上下文，不得改标为已实现财务事实；同一材料中的其它公司数据也不得移作目标公司事实。

### 11.4 资料变更与持续执行

运行中上传新资料后，增加 `reference_set_version`，先完成新增资料提取再发布覆盖快照。上传前已经发出的请求可能无法撤回，保留其原执行记录，但覆盖快照生效后结果不进入被覆盖字段的有效集合；尚未发出的请求立即取消或裁剪。

同字段已被新资料覆盖，关闭旧人工待办，旧 H/A/B 记录转为未采用。只使实际选用值、身份或引用变化的依赖失效；新增无关资料不重跑整个任务。报告已完成时建立新版本重新审核，旧版仍可追溯。

多份上传资料冲突时不以上传时间、报告发布日期或多数票自动选数；有明确修订关系或用户指定采用材料时才确定结果。人工选择或纠正绑定材料版本与目标字段，机器候选变化不能使其失效；原材料替换且对应内容发生变化时重新确认相关字段，其它字段保持。

验收必须检查实际外部调用记录：参考资料已覆盖字段的定向取数请求数为零；同时验证计算、正文、引用和终审均使用 R 数据，且缺失字段正常补齐。
