# v1.2 阶段成果获取与评估出口验收

日期：2026-10-10。范围：PRD 第 13 节与 F 阶段；验证均为本地、合成或 Mock HTTP，不代表真实模型和真实公司研究质量通过。

## 实现

- 独立 `work_products.py` 负责允许字段投影、脱敏、成果盘点、快照、分页预览以及 JSON/Markdown/ZIP 导出。正式 `report/download` 的批准判断和 DOCX/PDF 渲染函数保持原逻辑。
- SQLite 增加 `work_product_snapshots`、`work_product_reviews`、`work_product_materials` 三个旁路表。原 runs、records、checkpoints、reports、events 表及读取合同保留。
- 导出通过单次 SQLite 读事务固定已提交状态，再持久保存不可变快照；同一 run/snapshot 可在重启后读取。指定快照丢失、跨 run、超限或存储异常均明确返回错误，不换成最新内容。
- 每轮终审保存送审内容与对应意见；审核开始时保存 pending 候选，完成后写 rejected/reviewed/approved。旁路保存失败只记录安全日志，不改变原审核路由、异常或批准结果。
- 提取批次已通过绑定的证据/事实、已校验假设和已生成场景计算独立留存，避免后续模型调用失败使尚未提交主图检查点的材料不可获取。它们不注入正式事实库、模型上下文或恢复逻辑。
- Writer 的既有章节记录增加输入快照、依赖版本与生成时间。模型调用记录增加模型名、协议和系统提示摘要哈希，不保存提示正文。旧数据缺字段如实说明未知。
- 包含计划/覆盖、来源定位与必要摘录、事实及比较、公式版本/输入引用、假设/预测、块分析、章节、当前审核问题、送审历史、脱敏事件与实际/缺失用量。有效事实与隔离提案分开；完整来源正文、请求、认证、系统提示和隐藏推理不打包。
- 生成、校验、版本状态分开表达；重述及依赖变化标记失效，章节预览和 Markdown 分区显示历史失效内容。有效终审批准仅标记对应的成稿快照范围，不批准全部历史诊断。
- ZIP 的 manifest 包含记录数、文件字节数与 SHA-256；JSON/Markdown/ZIP 不依赖正式渲染器。默认 50,000,000 字节限制，超限报错不静默截断。
- 原单页进度区增加查看/导出入口，支持当前快照下载、显式获取最新快照、分页、下载失败重试、刷新后访问。没有 Report 的任务显示尚无写作成果，并可导出数据/诊断。

## 重跑

后端：`.venv/Scripts/python.exe -m pytest backend/tests -q --basetemp=work/pytest-v12-rerun`。前端在 frontend 目录运行 `npm.cmd test`、`npm.cmd run build`。正常浏览器回归先启动隔离前后端，再指定 `CDR_E2E_BASE_URL` 运行 `npm.cmd run test:e2e`。

`work-products.spec.ts` 的两项故障浏览器场景需要隔离数据库中的阻断 run，通过 `CDR_E2E_WORK_PRODUCT_RUN` 传入；同库需有 `v12-empty-failed` 早期失败样例。未配置时这两项明确跳过，不影响正常研究测试。本次种子和数据库保存在 `work/v12-browser`，不提供生产故障注入 API。Windows 沙箱下异步事件循环及 Vite 临时缓存受限，本次完整测试获准在本地沙箱外运行；应用运行无需管理员权限。

## 边界

只保证已提交且可读的材料。旧任务没有保存的送审轮次、未提交内存片段和供应商 usage 无法补回。数据库整体不可读时返回具体不可获取错误；单条 JSON 记录损坏时清单登记并导出其余可读范围。旁路保存为尽力保存，磁盘故障不能承诺完整恢复。真实模型/搜索联调、代表性真实公司评估和成本对比仍属未完成的 E 阶段。
